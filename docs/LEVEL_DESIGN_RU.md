# Руководство по дизайну уровней Code Quest

## Общие принципы создания уровней

### 1. Прогрессирующая сложность
Каждый уровень должен постепенно вводить новые концепции программирования:
- Уровни 1-5: Основы последовательности команд
- Уровни 6-10: Циклы и повторение
- Уровни 11+: Условные операторы

### 2. Обучение через игру
Каждый уровень должен:
- Иметь четкую образовательную цель
- Быть решаемым разными способами
- Предоставлять обратную связь игроку

### 3. Баланс сложности
- Оптимальное количество команд должно быть достижимо
- Максимальное количество команд не должно быть чрезмерным
- Уровень должен иметь несколько решений разной эффективности

## Создание LevelData ScriptableObject

### Базовые параметры уровня
1. **Level Index** - Уникальный номер уровня (начиная с 1)
2. **Level Name** - Название уровня на русском языке
3. **Description** - Краткое описание цели уровня
4. **Difficulty** - Сложность от 1 до 5
5. **Max Commands** - Максимальное количество команд для решения
6. **Optimal Commands** - Оптимальное количество команд для 3 звезд

### Параметры робота
1. **Start Position** - Начальная позиция робота (x, y)
2. **Start Direction** - Начальное направление (0=Север, 1=Восток, 2=Юг, 3=Запад)

### Цели уровня
1. **Goal Positions** - Массив позиций целей
2. **Require All Goals** - Требуется ли достижение всех целей (обычно false)

### Параметры сетки
1. **Grid Width/Height** - Размеры игровой сетки
2. **Grid Layout** - Визуальный редактор сетки

### Доступные команды
- Move Forward
- Turn Left
- Turn Right
- Jump
- Interact
- Repeat
- If
- Else

## Рекомендации по дизайну уровней

### Уровень 1 (Обучение)
**Цель:** Ознакомление с интерфейсом и базовым движением
- Размер сетки: 5x5
- Начальная позиция: (0,0), направление восток
- Цель: (4,0)
- Доступные команды: только Move Forward
- Оптимальное решение: 4 команды
- Максимум: 6 команд

### Уровень 2 (Повороты)
**Цель:** Введение поворотов
- Размер сетки: 5x5
- Начальная позиция: (0,0), направление восток
- Цель: (0,4)
- Доступные команды: Move Forward, Turn Left, Turn Right
- Оптимальное решение: 6 команд (4 поворота + 2 движения)
- Максимум: 10 команд

### Уровень 3 (Прыжки)
**Цель:** Использование прыжков для преодоления препятствий
- Размер сетки: 7x7
- Начальная позиция: (0,0), направление восток
- Цель: (6,0)
- Препятствия: стены на (2,0) и (4,0)
- Доступные команды: Move Forward, Turn Left, Turn Right, Jump
- Оптимальное решение: 5 команд (2 прыжка + 3 движения)
- Максимум: 10 команд

### Уровень 4 (Взаимодействие)

- Размер сетки: 7x7

## Использование редактора сетки

### Типы элементов сетки
1. **Empty** - Пустая клетка (по умолчанию)
2. **Wall** - Стена (нельзя пройти)
3. **Goal** - Цель (дополнительные цели)
4. **Pit** - Яма (провал уровня)
5. **Button** - Кнопка (взаимодействие)
6. **Door** - Дверь (открывается кнопками)
7. **Key** - Ключ (для открытия дверей)

### Работа с редактором
1. Выберите LevelData в инспекторе
2. Установите размеры сетки (Grid Width/Height)
3. Используйте Grid Editor для размещения элементов:
   - Левый клик - выбрать тип элемента
   - Правый клик на клетке - установить элемент
4. После размещения нажмите "Serialize Grid"
5. Сохраните ассет

## Тестирование уровней

### Процедура тестирования
1. Откройте сцену уровня
2. Проверьте начальную позицию робота
3. Проверьте достижимость всех целей
4. Протестируйте оптимальное решение
5. Протестируйте неоптимальные решения
6. Проверьте граничные условия
7. Убедитесь в корректности подсчета звезд

### Критерии качества уровня
- **Решаемость:** Уровень должен иметь хотя бы одно решение
- **Баланс:** Оптимальное решение должно быть достижимо
- **Образовательная ценность:** Уровень должен обучать новой концепции
- **Интересность:** Уровень должен быть увлекательным
- **Надежность:** Уровень не должен иметь багов

## Локализация уровней

### Названия уровней
- Используйте понятные названия на русском языке
- Названия должны отражать цель или механику уровня
- Примеры: "Первые шаги", "Повороты", "Прыжки", "Лабиринт"

### Описания уровней
- Кратко описывайте цель уровня
- Указывайте новые концепции, которые будут изучены
- Примеры: "Научитесь поворачивать робота", "Используйте прыжки для преодоления стен"

## Советы по дизайну

### 1. Постепенное введение сложности
- Не вводите сразу несколько новых концепций
- Давайте игроку время освоить каждую концепцию
- Создавайте уровни-мосты между сложными концепциями

### 2. Визуальная ясность
- Используйте четкие визуальные различия между элементами
- Обеспечьте хорошую видимость целей
- Избегайте перегруженности элементами

### 3. Обратная связь
- Делайте результаты действий игрока очевидными
- Предоставляйте визуальную обратную связь при взаимодействии
- Показывайте путь робота во время выполнения программы

### 4. Множественные решения
- Создавайте уровни с несколькими путями решения
- Поощряйте креативные подходы
- Балансируйте между простыми и сложными решениями
