# Руководство разработчика Code Quest


## Требования к окружению разработки

### Необходимое ПО
1. **Unity 6000.0 или выше**
2. **Visual Studio 2019 или выше** (или любой другой IDE с поддержкой C#)
3. **Git** для контроля версий
4. **Доступ к репозиторию проекта**

### Рекомендуемые инструменты
1. **JetBrains Rider** - альтернатива Visual Studio
2. **Unity Editor** - для работы с сценами и ассетами
3. **Miro** - для планирования и проектирования

## Структура проекта

```
Assets/
├── Scripts/
│   ├── Core/              # Основная игровая логика
│   ├── UI/                # Компоненты пользовательского интерфейса
│   └── Utilities/         # Вспомогательные классы
├── Prefabs/               # Префабы игровых объектов
├── Resources/             # Ресурсы, загружаемые в runtime
├── Scenes/                # Игровые сцены
└── Art/                   # Визуальные ассеты
```

## Архитектура проекта

### Основные принципы
1. **Синглтоны** - ключевые менеджеры реализованы как синглтоны
2. **Событийная модель** - loose coupling между компонентами
3. **Component-based design** - все функциональности реализованы как компоненты Unity
4. **ScriptableObjects** - для данных уровней и настроек

### Ключевые менеджеры
1. **GameManager** - центральный координатор игры
2. **LevelManager** - управление уровнями
3. **ProgramInterpreter** - интерпретатор программ
4. **RobotController** - управление роботом

## Стиль кодирования

### Соглашения о наименовании
1. **Классы** - PascalCase (например, `RobotController`)
2. **Методы** - PascalCase (например, `MoveForward`)
3. **Поля** - camelCase с префиксом `_` для private (например, `_currentLevel`)
4. **Константы** - UPPER_SNAKE_CASE (например, `MAX_COMMANDS`)
5. **Пространства имен** - соответствуют структуре папок

### Пример форматирования
```csharp
public class ExampleClass : MonoBehaviour
{
    [SerializeField] private int _exampleField;
    private static readonly string ConstantName = "Value";
    
    public int PublicProperty { get; set; }
    
    private void Start()
    {
        // Комментарии на русском языке для сложной логики
        InitializeComponent();
    }
    
    private void InitializeComponent()
    {
        // Реализация метода
    }
}
```

## Работа с Git

### Стратегия ветвления
1. **main** - стабильная версия
2. **develop** - текущая разработка
3. **feature/название-функции** - для новых функций
4. **bugfix/название-бага** - для исправления багов

### Коммиты
- Используйте императивное наклонение
- Пишите комментарии на русском языке
- Указывайте номер задачи в начале коммита
- Пример: `#123 Добавлена команда прыжка`

### Pull Requests
1. Создавайте PR из feature-ветки в develop
2. Добавляйте описание изменений
3. Прикрепляйте скриншоты при визуальных изменениях
4. Ожидайте код-ревью от коллег

## Тестирование

### Unit-тесты
- Размещаются в папке `Tests`
- Покрывают основную логику команд
- Запускаются через Unity Test Runner

### Интеграционное тестирование
- Тестирование взаимодействия компонентов
- Проверка сценариев использования
- Ручное тестирование в редакторе Unity

### Профилирование
- Используйте Unity Profiler для оптимизации
- Следите за утечками памяти
- Оптимизируйте производительность UI

## Лучшие практики

### Производительность
1. Используйте object pooling для часто создаваемых объектов
2. Минимизируйте вызовы GetComponent
3. Кэшируйте ссылки в Start/Awake
4. Используйте корутины вместо Update при возможности

### Безопасность
1. Проверяйте null-ссылки
2. Используйте события вместо прямых вызовов
3. Очищайте слушатели событий в OnDestroy
4. Останавливайте корутины при уничтожении объектов

### Поддержка кода
1. Пишите понятные комментарии
2. Следуйте единому стилю кодирования
3. Пишите документацию для новых функций
4. Покрывайте код тестами
